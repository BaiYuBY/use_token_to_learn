生成一个词元，大模型要把全部权重和整个 KV 缓存从显存读一遍。这一页从显存账本出发，依次演示 KV 缓存、量化、投机解码和 FlashAttention。第 4 节的两个模型直接在浏览器里运行。 To generate one token, a model reads all its weights and its whole KV cache from memory. This page starts from that memory bill, then shows the KV cache, quantization, speculative decoding and FlashAttention. The two models in section 4 run right in your browser.

1显存账本与解码速度The memory bill and decoding speed

显存 = 权重 + KV 缓存（每条序列每个词元都要存一份）。逐词元解码时，每一步要把权重和所有序列的 KV 缓存读一遍，所以速度通常受显存带宽限制：每步时间 ≈ max(读取字节数 / 带宽, 计算量 / 算力)。批量越大，权重的读取被更多序列分摊；但 KV 缓存随批量和上下文线性增长，很快成为瓶颈。数字按厂商标称的理想值估算，实际通常只能达到 50–70%。 Memory = weights + KV cache (stored for every token of every sequence). In token-by-token decoding, each step reads the weights and every sequence's KV cache, so speed is usually limited by memory bandwidth: step time ≈ max(bytes read / bandwidth, FLOPs / compute). A bigger batch shares the weight reads across more sequences, but the KV cache grows with batch and context and soon dominates. Estimates use ideal spec-sheet numbers; real systems usually reach 50–70%.

2KV 缓存：算过的 key 和 value 不再重算KV cache: never recompute a key or value

注意力里，每个新词元的 query 要和前面所有词元的 key、value 打交道。前面词元的 K、V 在之前的步骤里已经算过；不缓存就要每一步把整段重新算一遍（橙色），缓存后每步只算一个新位置（橙色），其余直接读取（浅蓝）。代价是 KV 缓存要占显存。 In attention, each new token's query meets the keys and values of all earlier tokens. Those K and V were computed in earlier steps; without a cache every step recomputes the whole sequence (orange), with a cache only one new position is computed (orange) and the rest is read back (light blue). The price is the memory the cache occupies.

3量化：用更少的比特存权重Quantization: fewer bits per weight

下面是目标模型第 1 层前馈网络的真实权重（256 × 64）。对称量化把每个权重除以缩放因子、四舍五入到整数，再乘回去。缩放因子越“局部”（整个张量 → 每行 → 每 32 个一组），越能适应各处不同的数值范围，但要多存一些缩放因子。打开“离群值”，看一个大权重如何毁掉整个张量的精度。 Below are the real weights of the target model's first feed-forward layer (256 × 64). Symmetric quantization divides each weight by a scale, rounds to an integer and multiplies back. The more local the scale (whole tensor → each row → each group of 32), the better it fits the local range, at the cost of storing more scales. Turn on the outlier to see one large weight ruin the precision of a whole tensor.

4投机解码：小模型起草，大模型一次验证Speculative decoding: a small model drafts, the big one verifies in one pass

草稿模型（小）先连续猜 k 个词元，目标模型（大）一次前向就能给这 k 个位置都打分。按 min(1, p/q) 的概率逐个接受；第一次被拒时，从 max(0, p − q) 重新采样一个并结束本轮；全部接受则白送一个词元。这个规则保证输出分布和只用大模型完全相同，草稿模型只影响速度。两个模型都在你的浏览器里运行。 The draft model (small) guesses k tokens in a row, and the target model (big) scores all k positions in a single forward pass. Each proposal is accepted with probability min(1, p/q); at the first rejection, one token is resampled from max(0, p − q) and the round ends; if all are accepted, one extra token comes free. This rule makes the output distribution exactly the target's; the draft only affects speed. Both models run in your browser.

5FlashAttention：分块计算，不存 T × T 的分数矩阵FlashAttention: work in tiles, never store the T × T score matrix

标准注意力先算出完整的 T × T 分数矩阵再做 softmax，长度翻倍、显存翻四倍。FlashAttention 每次只把一小块 query 和 key 搬进 GPU 的片上高速缓存，用“在线 softmax”边算边合并：维护每行的当前最大值 m 和累加和 l，遇到更大的分数时把旧的累加量乘以 exp(m旧 − m新)。结果与标准注意力完全相同（不是近似）。 Standard attention builds the full T × T score matrix before the softmax, so doubling the length quadruples the memory. FlashAttention moves one small tile of queries and keys into the GPU's on-chip memory at a time and merges results with an online softmax: it keeps each row's running max m and running sum l, and when a larger score arrives it rescales the old sums by exp(mold − mnew). The result is exactly standard attention, not an approximation.
