1训练要多少算力：C ≈ 6NDTraining compute: C ≈ 6ND

每个参数处理每个训练词元，前向约 2 次运算、反向约 4 次，合计约 6 次。再除以 GPU 的峰值速度和实际利用率（MFU），就得到要用多少 GPU 小时。选一个真实模型，或者自己拖动。 Each parameter costs about 2 operations per training token in the forward pass and about 4 in the backward pass, about 6 in total. Divide by the GPU's peak speed and the fraction actually achieved (MFU) to get GPU-hours. Pick a real model, or drag the sliders yourself.

2每个词元的计算花在哪里Where each token's compute goes

前向计算中，每个权重做一次乘加（2 次运算）。前馈网络和注意力的投影都与上下文长度无关；注意力打分（q·k）和加权求和（·v）则要看前面所有词元，随上下文变长而增长。拖动上下文长度看看构成如何变化。 In the forward pass every weight does one multiply-add (2 operations). The feed-forward network and the attention projections do not depend on the context length; attention scores (q·k) and the weighted sum (·v) look at every earlier token, so they grow with the context. Drag the context length and watch the mix change.

3推理：受算力还是受显存带宽限制？Inference: limited by compute or by memory bandwidth?

逐词元生成时，每一步都要把全部权重和每个请求的 KV 缓存从显存读一遍。一步所需时间 ≈ max(运算量 ÷ 算力, 读取字节数 ÷ 带宽)。批越大，同一份权重被越多请求共用。模型结构沿用第 2 节的选择。 When generating token by token, every step reads all the weights, plus each request's KV cache, from GPU memory. Step time ≈ max(FLOPs ÷ compute speed, bytes read ÷ bandwidth). A larger batch shares the same weights across more requests. The model architecture is the one chosen in part 2.

4和 RNN、KNN 比：贵在哪里Compared with RNNs and KNN: what costs more

假设一个 Transformer 和一个 RNN 的参数量相同（都用第 2 节的模型），处理一段长度为 T 的序列。两者每个词元的权重计算都是 2N，差别在于注意力、能否并行，以及生成时要保存的状态。KNN 不训练，每次查询都要与全部 n 个样本比较。 Suppose a Transformer and an RNN have the same number of parameters (the model from part 2) and process a sequence of length T. Both spend 2N per token on their weights; they differ in attention, in parallelism and in the state kept while generating. KNN does no training, but every query is compared with all n stored examples.
