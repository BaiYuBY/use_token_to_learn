把模型当成一个会出错的部件，在外面搭系统：拆分步骤、校验重试、多次投票、不确定就拒答、引用核对防编造。每个滑块背后都是同一组公式；第 2 节还有 11 章小模型的实测数据。 Treat the model as a component that makes mistakes and build a system around it: split the steps, validate and retry, vote, abstain when unsure, and check quotes against the source. Every slider runs the same formulas; section 2 also shows measurements from chapter 11's small model.

1误差会累积：少让模型做，多让代码做Errors compound: let code do what code can

一个流程由 n 个模型步骤串起来，每步正确率 p，整体正确率就是 pn。把其中确定性的步骤（计算、查表、规则判断）交给代码，它们的正确率就是 100%。 A pipeline of n model steps, each right with probability p, is right with pn. Hand the deterministic steps (arithmetic, lookups, rules) to code and those become 100% right.

2校验 + 重试：校验器能看到的错误才会消失Validate and retry: only errors the validator sees go away

每次尝试正确率 p。程序校验器（JSON Schema、取值范围、业务规则）能拦下比例为 c 的错误答案，拦下就重试，最多 r 次；全部被拦下的转人工。漏网的错误会被直接接受，所以准确率的上限是 p / (p + (1−p)(1−c))。 Each attempt is right with probability p. A programmatic validator (JSON Schema, ranges, business rules) rejects a fraction c of the wrong answers and triggers a retry, up to r attempts; if all are rejected, a human takes over. Errors it misses are accepted, so accuracy is capped at p / (p + (1−p)(1−c)).

3多次采样投票：分散的错误会被压过，一致的错误会被固定Majority vote: scattered errors are outvoted, consistent ones are locked in

现实中的题目有难有易。设一部分是简单题（模型常对），其余是难题（模型常错）。错误答案越分散（选项越多），多数票越容易选中正确答案；如果模型在难题上总是犯同一个错，投票只会把这个错误确认下来。 Real questions vary in difficulty. Some are easy (the model is usually right), the rest hard (usually wrong). The more the wrong answers scatter over options, the easier it is for the majority to land on the right one; if the model always makes the same mistake on a hard question, voting just confirms it.

4票数不够就转人工：用覆盖率换准确率Hand off when the votes disagree: trade coverage for accuracy

沿用第 3 节的题目和 k 次采样。只有得票最多的答案拿到至少 t 票时才自动作答，否则转人工。t 越高，自动作答的比例越低，但答出来的更可靠。这也是检测“编造”的一种办法：编造的细节每次采样都不一样。 Same questions and k samples as section 3. Answer automatically only when the top answer gets at least t votes; otherwise hand it to a human. A higher t answers fewer questions, but the answers given are more often right. This is also a way to catch fabrication: invented details change from sample to sample.
