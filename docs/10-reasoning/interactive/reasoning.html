1先思考，还是直接回答？Think first, or answer right away?

题目：从一个数字出发，从左到右做 k 次 “+d” 或 “×d”，每步只留个位。模型每生成一个字符，只做一次固定量的计算。直接作答时，它要在写下答案的那一个字符里完成全部 k 步；先思考时，它每写一个中间结果只需要算一步。同一个模型，两种模式的正确率差别巨大。 The task: start from a digit and apply k operations “+d” or “×d” from left to right, keeping only the last digit. Each character the model generates gets one fixed amount of computation. Answering directly, it must do all k steps inside the single character of the answer; thinking first, each intermediate result needs only one step. Same model, very different accuracy.

2思考预算：想到一半被打断会怎样？Thinking budget: what if thinking is cut short?

只允许模型写前 B 个思考字符，然后强制它写 “A:” 作答（s1 论文的 budget forcing 就是这样控制思考长度的）。k 步的题需要 2k − 1 个字符才能想完：预算够了，正确率才会跳上去。难题需要更长的思考。 Let the model write only the first B characters of its thinking, then force it to write “A:” and answer (this is how the s1 paper's budget forcing controls thinking length). A k-step problem needs 2k − 1 characters to finish thinking: accuracy only jumps once the budget is enough. Harder problems need longer thinking.

3多采样几次：投票，还是验证？Sample more: vote, or verify?

另一种花测试时算力的方法：同一道题采样 n 条推理。“多数投票”（self-consistency）选出现最多的答案；“pass@n”假设有一个验证器，只要 n 条里有一条对就算对。这里用一个训练不足的模型，在 6–12 步的难题上测试。 Another way to spend test-time compute: sample n reasoning chains per problem. Majority voting (self-consistency) takes the most common answer; pass@n assumes a verifier and counts a problem solved if any of the n chains is right. Tested here with a lightly trained model on hard problems of 6–12 steps.

4GRPO：只靠“对不对”学推理GRPO: learning to reason from right-or-wrong alone

DeepSeek-R1 的做法：同一道题采样一组回答，用规则判对错（不需要奖励模型），每个回答的优势 = (它的得分 − 组内平均) ÷ 组内标准差。点击下面 8 个回答切换对错，看优势怎么变：全对或全错时，优势全为 0，这一组就什么也学不到。 DeepSeek-R1's recipe: sample a group of answers to the same problem, judge each with a rule (no reward model), and give each answer an advantage = (its score − group mean) ÷ group std.
