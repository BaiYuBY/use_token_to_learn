代码和文字最大的不同：代码可以运行，对不对可以用测试来判断。这一页的数据都来自本章代码训练的一个小模型：给它函数头和一行注释（比如 “# add 3, double, square”），它写出函数体。训练数据里的函数有 1–6 步。 The big difference between code and prose: code runs, so tests can tell whether it is right. Everything on this page comes from a small model trained by this chapter's code: given a function header and a one-line comment (such as “# add 3, double, square”), it writes the body. Training functions have 1–6 steps.

1中间填空（FIM）：光标在函数中间Fill-in-the-middle (FIM): the cursor is inside a function

写代码时，光标往往在文件中间，下面还有代码。从左到右的语言模型只能接着前缀往下写。FIM 训练把文件切成前缀、中间、后缀三段，把中间挪到最后，用特殊标记隔开；模型照常预测下一个词元，却学会了“看着两边填中间”。选一个函数和一段空缺，比较两种模型的补全。 When you edit code the cursor is usually mid-file, with code below it. A left-to-right model can only continue the prefix. FIM training cuts a file into prefix, middle and suffix, moves the middle to the end and separates the pieces with special tokens; the model still just predicts the next token, but learns to fill a gap using both sides. Pick a function and a gap, and compare the two completions.

2pass@k：采 k 个，至少一个通过测试的概率pass@k: the chance that at least one of k samples passes

对每道题采样 n 个程序（n ≥ k），其中 c 个通过全部单元测试。无偏估计是 1 − C(n−c, k) / C(n, k)：从 n 个里不放回地抽 k 个，全都失败的概率，再取补。看似自然的 1 − (1 − c/n)k 会系统性偏低。设一个真实通过率 p，点“模拟”看看。 For each problem, sample n programs (n ≥ k), of which c pass all unit tests. The unbiased estimate is 1 − C(n−c, k) / C(n, k): one minus the chance that k drawn without replacement from the n all fail. The tempting 1 − (1 − c/n)k is biased low. Set a true pass rate p and press “simulate”.

3实测：函数越长越难，多采样能补回多少Measured: longer functions are harder; how much do more samples recover?

每种长度 40 道题，每题采样 20 个程序，用 11 个输入（−5…5）做单元测试。7 步的函数比训练数据里最长的还多一步。换一个采样温度看看。 40 problems per length, 20 programs sampled for each, unit-tested on 11 inputs (−5…5). Seven steps is one more than anything in the training data. Try another sampling temperature.

5从测试中学习：只用自己写对的程序微调Learning from the tests: fine-tune only on its own correct programs

每轮出 300 道 5–6 步的题，每题采样 8 个程序，留下通过全部单元测试的，和原始训练数据混在一起微调 200 步。没有人写“标准答案”，唯一的信号是测试通过与否。这是拒绝采样微调，也是可验证奖励强化学习（第 10 章）最简单的形式。 Each round poses 300 problems of 5–6 steps, samples 8 programs for each, keeps those passing every unit test and fine-tunes 200 steps on them mixed with the original training data. Nobody writes reference solutions; the only signal is pass or fail. This is rejection-sampling fine-tuning, the simplest form of reinforcement learning from verifiable rewards (chapter 10).
