长上下文 · 交互演示Long Context · Playground

让模型读更长的文本，要过两关：位置编码在没见过的长度上会不会“失灵”，以及注意力的计算量和 KV 缓存会不会爆炸。实测部分来自一个在 64 个词元上训练、用 RoPE 编码位置的小 GPT。 Reading longer text means clearing two hurdles: does the position encoding break at lengths it never saw, and do attention compute and the KV cache explode? The measurements come from a small GPT with RoPE, trained on 64-token windows.

1RoPE 为什么会“失灵”：每对维度转了几圈Why RoPE breaks: how far each pair of dimensions turns

RoPE 把 q、k 的每两维看成一个平面上的点，按“位置 × 频率”旋转，注意力分数只取决于两个词元的相对距离。快的维度对在训练长度内转了很多圈，什么角度都见过；慢的维度对连一圈都没转完，训练时只见过一小段角度。测试时序列更长，这些慢维度就转到了从没见过的角度（红点）。位置插值（PI）把所有频率按比例调慢；NTK 调大底数，主要拉伸慢的维度；YaRN 只拉伸转不满一圈的维度。 RoPE treats every two dimensions of q and k as a point in a plane and rotates it by position × frequency, so attention scores depend only on the distance between tokens. Fast pairs turn many times within the training length and have seen every angle; slow pairs don't complete one turn, so training only showed them a narrow range of angles. At a longer test length those slow pairs reach angles never seen (red dots). Position interpolation (PI) slows every frequency by the same factor; NTK raises the base, stretching mostly the slow pairs; YaRN stretches only the pairs that don't complete a turn.

3注意力模式：哪些位置要算Attention patterns: which positions are computed

每一行是一个查询词元，每一列是它能看的 key（只看自己和之前的）。全注意力的计算量随长度平方增长；滑动窗口只看最近 w 个；“汇聚点”（attention sink，StreamingLLM）额外保留开头几个词元；空洞注意力隔几个看一个；块稀疏（BigBird / Longformer 式）组合局部、全局和随机；Top-k 块选择（MoBA、NSA 式）让每个查询按相关性挑几个块来看。 Each row is a query token and each column a key it may attend to (itself and earlier). Full attention grows with the square of the length; a sliding window sees the last w; attention sinks (StreamingLLM) also keep the first few tokens; dilated attention looks at every few positions; block-sparse (BigBird / Longformer style) mixes local, global and random; top-k block selection (MoBA, NSA style) lets each query pick the most relevant blocks.
