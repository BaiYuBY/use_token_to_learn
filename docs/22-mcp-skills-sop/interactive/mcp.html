三种把 agent 的能力“标准化”的办法：MCP 让工具和数据跨程序、跨语言可复用；Skills 把操作说明和脚本打包，需要时才加载；SOP 规定多个 agent 之间交接什么、怎么检查。下面的 MCP 消息都是真实录下来的：手写的服务器和官方 SDK 的服务器。 Three ways to standardize what an agent can do: MCP makes tools and data reusable across programs and languages; Skills package instructions and scripts that load only when needed; SOPs fix what agents hand to each other and how it is checked. The MCP messages below were recorded for real, from a hand-written server and from the official SDK's server.

1MCP：一条一条看消息MCP, message by message

MCP 是 JSON-RPC 2.0：客户端发请求（带 id），服务器回结果或错误；通知没有 id，也没有回复。本地服务器通过 stdio（每行一条消息）连接，远程服务器通过 HTTP。2026-07-28 版是无状态的：没有握手，每个请求都在 _meta 里带上协议版本和客户端能力（橙色高亮）。对比旧版的 initialize 握手。 MCP is JSON-RPC 2.0: the client sends requests (with an id), the server returns a result or an error; notifications have no id and get no reply. Local servers connect over stdio (one message per line), remote ones over HTTP. The 2026-07-28 revision is stateless: no handshake, and every request carries the protocol version and client capabilities in _meta (highlighted in orange). 2上下文预算：工具说明与 skill 放在哪里Context budget: where tool descriptions and skills go

    

      连接的每个 MCP 工具，说明都要放进每一次模型调用。skill 的正文往往很长（几百到几千词），如果全放进系统提示，很快就撑满上下文；渐进式披露只放每个 skill 的名字和描述，任务需要时再加载正文。拖动滑块看每次调用和整个任务要读多少词。
      Every connected MCP tool's description goes into every model call. Skill bodies are often long (hundreds to thousands of words); put them all in the system prompt and the context fills up fast. Progressive disclosure keeps only each skill's name and description, and loads a body when a task needs it. 3Skills：三层渐进式披露Skills: three levels of progressive disclosure

    

      一个 skill 就是一个文件夹：SKILL.md 开头的 YAML 写 name 和 description（第 1 层，始终在提示里），后面是说明（第 2 层，用到时加载），文件夹里还可以有脚本和参考文件（第 3 层，某一步需要时才读取或运行；脚本的代码不进入上下文，只有输出进入）。点开本章的 4 个真实 skill：
      A skill is a folder: the YAML at the top of SKILL.md gives a name and description (level 1, always in the prompt); the instructions follow (level 2, loaded when used); the folder may also hold scripts and reference files (level 3, read or run only when a step needs them; a script's code never enters the context, only its output). 4SOP：多个 agent 之间交接什么、怎么检查SOPs: what agents hand over, and how it is checked

    

      MetaGPT 的思路：像公司的标准作业程序一样，给每个角色规定输入、输出的格式和检查项，角色之间通过共享的消息池交接结构化产物，而不是互相聊天。这里 6 个角色依次处理一份公司报告；每次交接，每个事实都有一定概率被漏掉或改错。
      MetaGPT's idea: as in a company's standard operating procedures, give each role a fixed input, output format and checklist, and have roles hand structured artifacts to each other through a shared message pool instead of chatting. Here 6 roles work on a company report in turn; at every handoff each fact may be dropped or altered.
