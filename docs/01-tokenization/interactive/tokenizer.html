2BPE 训练：一步一步合并Training BPE, one merge at a time

规则只有一条：数一数所有相邻词元对出现的次数，把最多的那一对合并成一个新词元，然后重复。下面是经典的小例子（Sennrich 等，2016），你也可以改成自己的句子。“·”表示空格。 There is only one rule: count every pair of neighbouring tokens and merge the most frequent pair into a new token, then repeat. 3编码新词：按学到的顺序合并Encoding a new word: replay merges in order

编码时不再数频率，而是从字节出发，每次应用最早学到的、能用上的那条合并规则，直到无法再合并。训练时没见过的词也能编码，最坏情况就是退回到单个字节，所以字节级 BPE 永远不会出现“未知词”。 Encoding does not count anything. Starting from bytes, it repeatedly applies the earliest-learned merge that fits, until none does. Words never seen in training still work: at worst they fall back to single bytes, so byte-level BPE never needs an “unknown” token.

4词表大小的权衡The vocabulary-size trade-off

合并越多，词表越大，同样的文本需要的词元越少（序列更短、算得更快、上下文能装更多内容）；但嵌入矩阵和输出层都有“词表大小 × d_model”个参数，也会变大。拖动滑块观察内置语料的变化。 More merges mean a bigger vocabulary and fewer tokens for the same text (shorter sequences, faster compute, more text per context window). But the embedding table and the output layer each hold vocab size × d_model parameters, and those grow. Drag the slider and watch the built-in corpus.
